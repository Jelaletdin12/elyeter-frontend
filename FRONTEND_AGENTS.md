# AI / Agent İçin Katı Talimatlar — Frontend

Bu proje Next.js (App Router) + TypeScript + TanStack Query + Zustand + shadcn/Tailwind ile yazılmaktadır. Backend `AGENTS.md` / `BACKEND_STANDARDS.md`'deki sözleşmeye (response format, i18n key, rol matrisi, locale-bazlı slug) **birebir** uyulur. Detaylı gerekçeler için `FRONTEND_STANDARDS.md`'ye bakılmalıdır.

1. **Server state ile client state kesinlikle karıştırılmaz.** Backend'den gelen her şey (ürün, kategori, sipariş, sepet, kullanıcı) TanStack Query'de yaşar. Zustand sadece UI state (modal, drawer, wizard adımı) ve `activeStoreId`/oturum yansıması gibi client-only state için kullanılır. Zustand içine asla server response'u elle yazılmaz.
2. **`any` kesinlikle yasaktır.** Tip bilinmiyorsa `unknown` + type guard. Backend DTO tipleri elle kopyalanmaz — `openapi-typescript` ile backend'in Swagger şemasından otomatik üretilir (`pnpm generate:types`), commit edilir, elle düzenlenmez.
3. Her API çağrısı tek bir `apiFetch<T>()` client'ından geçer. Backend'in `{ success, data }` / `{ success: false, message, timestamp }` formatı sadece bu client içinde unwrap edilir — component içinde manuel `res.json()` veya `if (!success)` kontrolü yazılmaz.
4. Hata mesajları backend'den i18n key olarak gelir (`errors.product_not_found`). Bu key, component içinde değil, tek bir global error handler'da (`onError` — QueryClient default veya ToastProvider) `react-i18next` ile çözülür. Component'lerde hardcoded hata metni yazılmaz.
5. **Public/SEO sayfalar** (anasayfa, kategori listeleme, ürün detay) Server Component + `fetch(..., { next: { revalidate, tags } })` ile ISR olarak yazılır. **Private/kişisel sayfalar** (sepet, sipariş, hesap, admin panel) tamamen Client Component + TanStack Query'dir; bu sayfalarda Next.js Data Cache (`fetch` cache) **kullanılmaz**, `cache: 'no-store'` zorunludur.
6. Next Data Cache tag convention'ı sabittir: `products`, `product:{locale}:{slug}`, `categories`, `category:{locale}:{slug}`, `banners`, `home`. Yeni bir public/cacheable veri tipi eklenirse aynı `{tip}:{locale}:{slug}` deseni izlenir — ad hoc tag ismi üretilmez.
7. **Dual invalidation kuralı:** Admin panelinden (CSR) yapılan her mutation (ürün/kategori/banner create-update-delete), kendi TanStack cache'ini `invalidateQueries` ile temizledikten SONRA, ilgili public sayfanın Next Data Cache tag'ini temizlemek için `POST /api/revalidate` route handler'ını çağırır. Bu adım atlanırsa admin'de değişiklik görünür ama public sitede saatlerce eski veri kalır — bu, en sık atlanan ve en pahalıya patlayan hatadır.
8. `proxy.ts`'teki route guard (Next 16'nın middleware → proxy convention'ı) **sadece UX** içindir (cookie/flag var mı diye bakar, yanlış sayfaya yönlendirmeyi önler). Gerçek yetki sınırı backend'deki `@Roles()`/`RolesGuard`'dır — frontend guard'ı asla tek güvenlik katmanı olarak görülmez.
9. Rol bazlı UI gösterimi (`OPERATOR` şu butonu görmesin gibi) sayfa sayfa `if (user.role === ...)` ile yazılmaz. Backend'deki `ROLE_MANAGEMENT_MAP`/rol matrisiyle birebir eşleşen tek bir `useAuth().can(action)` hook'u üzerinden yapılır.
10. Access token **localStorage'da tutulmaz** (XSS riski). Access token yalnızca bellekte (Zustand, persist edilmeden) tutulur; refresh token backend'in döndürdüğü değeri Next.js route handler'ı httpOnly cookie olarak set eder. Sayfa yenilendiğinde silent-refresh route'u ile yeni access token alınır.
11. Görsel yükleme backend'in "önce yükle, sonra bağla" pattern'ine (`POST /media/uploads` → `mediaId` → entity create/update body'sinde referans) birebir uyar. Her entity için ayrı upload component'i yazılmaz — tek bir `useMediaUpload()` hook'u + tek bir `MediaUploader` shared component'i tüm context'lerde (`PRODUCT_IMAGE`, `BANNER_IMAGE`) kullanılır, preset/boyut bilgisi frontend'de tekrar tanımlanmaz (backend zaten resize ediyor, frontend sadece dönen URL varyantlarını gösterir).
12. Search sayfası (`/search?q=`) **Client Component + TanStack Query**'dir, Next.js Data Cache'e asla girmez — query param'a bağlı sonsuz kombinasyon cache'i şişirir ve backend'in `pg_trgm` tabanlı arama sonucu zaten anlık/kişiye özel davranabilir (debounce zorunludur, bkz. `FRONTEND_STANDARDS.md`).
13. Sepet/checkout sayfalarında **hiçbir veri Next.js tarafında cache'lenmez** (`export const dynamic = 'force-dynamic'`). Stok/fiyat kontrolü backend'de zaten canlı yapılıyor (`availableQuantity`, live `ProductVariant.price`) — frontend bunu eski bir cache'ten okuyup kullanıcıya yanlış bilgi göstermez.
14. Query key convention'ı sabittir: `[domain, storeId, ...params]` — örn. `['products', activeStoreId, filters]`. `storeId` şu an sabit/tek değer dönse bile key'in bir parçası olarak yazılır (ileride multi-store geçişi için).
15. Mutation sonrası **sadece TanStack `invalidateQueries` yetmez** — eğer aynı veri bir Server Component sayfasında da gösteriliyorsa (örn. admin'de düzenlenen ürün, aynı anda başka bir sekmede public detay sayfasında açık), ilgili sayfa `router.refresh()` ile de invalidate edilir; aksi halde Next.js Router Cache (client-side, session bazlı) eski RSC payload'ı göstermeye devam eder.
16. 2+ route/feature aynı UI parçasını (tablo, dialog, form input) kullanıyorsa `components/shared/` altına taşınır; tek yerde kullanılıyorsa kendi feature klasöründe kalır — aynı component iki kez yazılmaz.
17. Yeni bir sayfa/feature eklemeden önce mevcut feature'larda benzer bir pattern olup olmadığı kontrol edilir; var olan rendering/cache/state deseni tekrar icat edilmez.
